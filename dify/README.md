# Dify 工作流备份与恢复

本目录收录项目负责人于 2026-10-21 从 Dify 导出并提供的五份 DSL，保留原始文件内容，仅统一文件名。

| 文件 | 工作流 | 节点 | 连线 |
| --- | --- | ---: | ---: |
| demand.yml | AI协作草稿与需求审核 | 20 | 23 |
| capability.yml | 个人经历与能力草稿 | 10 | 11 |
| matching.yml | 供需匹配与证据解释 | 13 | 13 |
| team.yml | 组队组合、周分工与合作约定 | 41 | 52 |
| delivery.yml | 交付验收与贡献记录 | 16 | 22 |

合计 100 节点、121 连线、11 个模型节点，模型名称均为 deepseek-v4-flash。DSL 格式版本为 0.7.0；模型依赖由导出文件的 dependencies 字段记录。此前文档记载交付流程为 20 连线，现以此次实际导出的 22 连线为准。导出不证明草稿与已发布版本逐字一致，既有 API 测试仍对应测试当时的发布版本。

已完成 YAML 解析、节点 ID 唯一性、连线端点引用、Python 代码节点语法、已知密钥及常见密钥格式检查。五份导出均无环境变量条目。文件哈希及逐应用结果见 [backup_manifest.json](backup_manifest.json)。这属于静态核对，尚未在新账号进行导入运行测试。

## 恢复步骤

1. 在目标 Dify 工作室通过“导入 DSL”分别导入五份文件。现有账号有应用数量限制时，不要删除线上成果腾位置；应选择有足够容量的目标环境。
2. 根据依赖安装兼容的 DeepSeek 插件，并配置目标环境的模型凭据；检查模型名称、思考模式和输出参数是否受目标提供方支持。
3. 核对节点、分支、输入输出和人工表单；发布目标版本，为各应用创建服务 API 密钥。
4. 更新网站后端的应用配置与人工节点映射，运行本地检查，再进行目标环境 API 联调。旧测试结果不能代替迁移后的验证。

DSL 保存工作流定义，不备份模型凭据、历史运行、登录用户、数据库、已确认的合作记录或网站公开状态。完整项目还应保留本仓库中的后端适配代码和文档。
