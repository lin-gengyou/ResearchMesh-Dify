# 研织 ResearchMesh：用户主页内容与数据约定

本文件是新增功能的内容和接口设计，供后续网页 agent 实现；目前没有新建或发布网页，不是最终全项目交接书。

## 主页的用途

让潜在协作者看懂“这个人具体做过什么、希望怎样合作、哪些内容有依据”，也让本人维护科研协作名片。主页默认私有预览。匹配授权、本人确认经历、贡献草稿授权和公开主页授权是不同状态。

## 内容组成

| 区域 | 展示内容 | 数据来源与编辑方式 | 公开规则 |
| --- | --- | --- | --- |
| 名片 | 昵称、头像、可选学校/专业、一句话介绍 | 本人编辑；不从经历中自动挖掘联系方式 | 本人按字段选择；学校、专业均非必填 |
| 我做过什么 | 具体个人经历卡，说明本人动作及范围 | AI整理后的本人确认结果，可更正重整 | 按条选择；保留“本人自述、未经外部核验”等依据标签 |
| 想学什么 | 方向或工具，如 ROS2 | AI从经历中区分兴趣，再由本人编辑 | 独立选择公开，不能混成已有能力 |
| 合作意向 | 想参加的项目、希望承担的工作、合作方式 | 本人短句；如“愿从数据整理或小范围试协作开始” | 主页只显示粗粒度意向；具体时间表和联系方式默认私有 |
| 项目与贡献 | 项目名、本人职责、交付范围、验收/核对状态 | 已有合作和贡献流程；只展示本人的贡献 | 贡献必须单独获公开授权；允许生成公开草稿不等于已公开 |
| 本人管理区 | 待核对草稿、更正记录、待处理合作、可见范围管理 | 登录本人后读取受保护状态 | 他人视图永不包含该区域 |

后续可按真实数据支持添加“我发布的公开需求”“参与项目时间线”，不使用假的计数、徽章或认证补页面。没有贡献时使用真实空状态，不生成虚构科研经历。

## 个人能力卡的措辞

示例：

- **CSV 数据处理经历**：跟随教程使用 Python 处理 CSV 空值。依据：本人自述已核对，未经外部核验。完成方式：教程/指导下完成。
- **项目汇报整理**：本人整理团队项目汇报。该卡不代表本人编写机械臂控制代码。
- **正在学习**：ROS2。状态：兴趣或学习方向，不计为已掌握技能。

主页不生成“Python 85分”“科研能力 S 级”等无依据评级。“验收者通过”只对应当次交付；不得自动写成所有相关技能均已认证。

## 可见性与动作

本人视图可以查看主页预览、修改简介、按条选择公开内容、撤回公开、查看待核对内容。访客视图只拿到服务端过滤后的公开投影。禁止把所有私有字段发给浏览器后仅用 CSS 隐藏。

本人确认供匹配使用 → 只生成匹配线索，不会自动发布到主页。

贡献者允许生成公开草稿 → 只生成待发布稿，仍需一次独立的最终发布确认。正式实现时需校验真实登录人、内容版本与授权快照，并允许撤回。发布会扩大可见范围，执行最终动作前需对应用户授权。

“发起协作”应发送站内请求或进入需求讨论，不能直接暴露手机号或替双方成立合作。消息发送、邀请和公开发布需由未来网页后端实现；本阶段没有执行这些动作。

## 数据接口建议

| 网页接口（建议，尚未部署） | 返回/行为 |
| --- | --- |
| GET /api/me/home-preview | 本人完整预览及未公开状态 |
| PATCH /api/me/profile | 更新本人基础资料；字段白名单与长度校验 |
| POST /api/me/home-publications | 预览快照 hash、逐字段/逐卡选择；服务端鉴权后创建发布记录 |
| DELETE /api/me/home-publications/current | 撤回当前公开投影；保留必要审计记录 |
| GET /api/users/:id/home | 只返回已发布投影；未发布或撤回则为空状态 |

这些是网页后端的业务接口，不是 Dify 路径。Dify 负责经历整理和贡献处理；真实用户 ID、头像存储、登录、权限、数据库与发布记录由网页后端负责。

home_profile.py 是数据投影参考，区分 owner_preview 与 public。公共输出采用白名单，默认不含原始经历、引用全文、问题列表、私人更正、运行编号、精确日程或联系方式。它不实现鉴权、数据库或实际发布。

publication 只能来自受保护的服务端记录，不能相信前端自行传 status=published。记录必须绑定本人 ID、精确预览 hash 和选中的内容。项目贡献还需自己的内容 hash 授权；主页总体发布不代替贡献单独公开。

示例数据均为虚构或既有虚构功能测试结果；public_projection_sample.json 只是本地序列化样例，没有向任何网站公开发布。
