# 后续建设

## 工作流维护

已完成：三个上游密钥创建、五应用当前发布版 API 核验、需求与能力人工角色映射、96 项回归/权限测试及 9 项能力衔接断言。五份 DSL 已归档并完成静态核对。

迁移后的导入运行与 API 回归仍需在目标环境完成。

## 网页与服务端

| 优先级 | 工作 | 验收 |
| --- | --- | --- |
| 1 | 服务端配置密钥、启动及续接 Dify、保存 run/人工待办 | 断线接回同一 run，不盲目重新启动 |
| 1 | 用户登录、档案归属、需求负责人和承担者权限 | 旁人不能代确认，不能自行伪造 current |
| 1 | 业务数据库、版本快照、幂等键及事务复核 | 旧版本和重复提交不能覆盖当前状态 |
| 2 | 需求、经历、匹配、分工、约定、交付页面 | 只向用户显示可理解内容，机器包由后端装配 |
| 2 | 拒绝、退回、争议、超时、无解、无数据及服务错误 | 不把 Dify succeeded 一律写成业务成功 |
| 2 | 用户主页私有预览、逐条公开、贡献单独授权及撤回 | 访客响应不含私有字段 |
| 3 | 设计系统、响应式、可访问性、部署和最终网站发布 | 项目负责人审阅最终视觉和发布版本 |

消息/邀请、名额事务、材料存储等按网站真实功能范围实现；目前 Dify 没有执行这些外部动作。使用模拟数据做展示时必须明确标注，不制造已存在的真实用户网络、公开履历或认证。

页面视觉和素材整理、空状态文案、响应式与键盘可访问性检查、竞赛演示脚本排版、部署说明和非核心页面开发。提供研究包、产品功能介绍与最终交接书即可。涉及证据规则、换版确认、角色权限和跨应用契约时，需核对现有工作流契约。
